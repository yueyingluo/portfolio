02

User Agent 把目标拆成四个可验证子任务

规划者负责“接下来查什么”和“什么时候完成”，不直接操作工具。

SUBTASK 01

建立产业链框架：上游零部件与算力、中游本体与控制、下游应用场景。

SUBTASK 02

比较三类厂商：本体厂商、模型平台、场景方案商的产品和收入路径。

SUBTASK 03

补充商业证据：融资、订单、客户类型与规模化交付信号。

SUBTASK 04

补充技术证据：论文方法、训练数据、指标局限与政策方向。

Plan–Execute 解耦：User Agent 只发出高层语义指令，Assistant Agent 自主选择工具并返回标准化 Observation。

04

User Agent 读取中间证据并改写后续计划

渐进式搜索的关键不是多搜几次，而是根据缺口动态调整方向。

TURN 02 · READ

产业链结构已覆盖，但“商业化路径”仍只有二手观点，缺少融资与客户证据。

REPLAN

暂停泛化搜索，新增财务数据库与厂商公开页面检索，按公司、日期和客户类型归一化。

TURN 04 · READ

商业证据满足，但技术趋势缺少一手实验依据；新增近两年论文检索。

STOP CHECK

四项必达信息均有多源证据，冲突已标记，达到报告模板要求，终止搜索。

终止机制：完成度判断结合任务必达信息、差异化终止条件与共享最大轮数，避免循环和无效过度搜索。
