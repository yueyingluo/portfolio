01

PM 选择本轮关心的评测维度

业务目标先被翻译成可执行的 Evaluator 与准入条件。

策略是否覆盖“商品破损 + 已举证”场景​
Agent 是否完整执行举证核验 SOP​
赔付与流程是否满足业务护栏​
我搭建的入口：PM 不需要修改 Agent Prompt，只需配置关注维度、样本集和护栏，系统自动组织后续评测与优化。
02

系统读取一个“没有解决用户问题”的样本

对话、订单状态、Agent 方案和平台最终方案被组织为一条配对数据。

用户问题商品到货破损，已上传外包装与商品照片。
当前 SOP核验举证 → 判断责任 → 选择策略 → 告知下一步。
Agent 方案再次要求用户补充已经上传的商品照片。
平台方案举证已满足，进入责任判断并说明处理时效。
单看“最终没解决”还不知道该改什么：可能是策略根本不覆盖，也可能是 Agent 没执行好已有 SOP。下一步由双 Evaluator 分开判断。
03

双 Evaluator 把问题归因到“执行偏差”

双 Reward 同时保留用户目标与业务护栏，避免只追一个分数。

04

受控更新引擎只修改被证据支持的规则

失败反思产生 Add / Delete / Replace 操作，并限制编辑范围。

CURRENT / v11

若商品破损，要求用户上传外包装与商品照片；材料齐全后进入责任判断。

CANDIDATE / v12 · ADD

新增：先读取会话与订单中的举证状态；材料已存在时不得重复索取，直接进入下一 SOP 节点。
